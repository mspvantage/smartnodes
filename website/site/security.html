Security and privacy

Status

SmartNodes is an early test network. Its design has not yet been reviewed by an independent cryptographer, and its code has not been audited. Do not rely on it where your safety depends on it.

Tickets on the test network are signed by one test key and have no value. The test network may be reset at any time.

What it is built to protect

  • Who paid. Tickets are blind-signed: when a node is paid, nobody can tell which purchase the ticket came from.
  • Who you are, from where you go. No single node sees both your address and your destinations; the two hops are run by different operators.
  • Timing. Paying the exit and using it are separated by a random wait, so the chain's record of a payment cannot be matched to when you connected.
  • That you use a VPN at all, from a casual observer, when the disguise is in use: the connection looks like a visit to a well-known website.
  • Leaks. A kill switch stops traffic if the tunnel drops; name lookups go through the tunnel; IPv6 is closed off rather than leaked.
  • Records. Nodes keep session details in memory only and log only totals.

What it does not protect

  • An entry and an exit working together, or one party watching the internet near both, can match traffic going in with traffic coming out. Choose an entry and exit run by operators you have reason to think are unrelated.
  • What you reveal yourself. Signing in to an account tells that website who you are, whichever node you use.
  • A compromised device. Nothing on the network can help if the device itself is watched.
  • The exit's view. The exit sees unencrypted traffic, as with any VPN. Use HTTPS.
  • Buying tickets is a public payment from some account. Nothing links it to spending the tickets, but the account that pays is known to have bought tickets.

If a node is dishonest

  • A node cannot serve without being paid, and cannot be paid twice for one ticket.
  • Probers chosen at random test nodes through real sessions; nodes that fail are hidden, and nodes proven to tamper lose bond.
  • A bridge that hands out a false line is proven wrong on the chain and loses bond.
  • An exit that lies about a bridge answer is caught by asking a second node.
  • An operator can still log what their node sees, despite the software. Two hops exist so that what any one node sees is not enough.

Against censors

A censor can block every node on the public list. The disguise makes connections hard to recognise; bridges give entry points on no list, each costing a ticket and handed to only a few people. A well-funded censor can still buy bridge lines. Bridges are designed so that collecting them is slow and costly, that what the censor pays goes to bridge operators, and that a blocked bridge is quick to replace. No system has fully solved this.

Reviews and audits

Before any network carries real value, the plan is:

  1. An independent cryptographer reviews the ticket scheme, threshold issuers, the bridge sealing and the planned proof that probes happened.
  2. An independent security audit of the chain modules and the VPN code.
  3. A public test network with outside operators and probers.

Reports from each will be published here.

Report a security problem

Please report security problems privately, through GitHub's private vulnerability reporting:

Report a vulnerability privately

Please do not open a public issue for a security problem. Say what you found, how to reproduce it, and what it could let someone do. You will get a reply, and credit if you would like it.
