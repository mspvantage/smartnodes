Run a node

This guide takes a fresh Linux server to a working SmartNodes VPN node. Every step ends with a check; do not move on until it passes. On the test network tokens have no value, so this is the time to learn.

The public test network has not launched yet. Values shown as PUBLISHED_AT_LAUNCH will be filled in here when it does. You can practise every step now on a local test chain.

Kinds of node

KindWhat it doesSeesBond (draft)
Entry (tier 1)First hop. Can offer the disguise.Users' addresses, not where they go1,000 SNODE
Exit (tier 2)Second hop: traffic leaves to the internet from here.Where traffic goes, not who sent it5,000 SNODE
BridgeAn unlisted entry, reached only through the disguise.Like an entryAt least 1,000 SNODE
Running an exit means other people's traffic leaves to the internet from your address. Check your hosting provider's terms and your local law first. An entry or bridge carries much less of this risk. Never run an entry and an exit for the same users on the same server or provider account: two hops only protect people if they are separate.

What you need

  • A Linux server (Ubuntu or Debian) with a fixed public IPv4 address and root access. 2 CPU cores and 2 GB of memory are enough to start; an exit needs good bandwidth.
  • Your own computer, for your operator key. It controls the bond, so it never goes on the server.
  • Test SNODE for the bond and fees, from the faucet.
  • Access to the chain: a public endpoint, or better, your own chain node (see Run a validator, steps 1 to 7; a node does not need to be a validator).

Set these in every terminal, on the server and on your computer. If you run your own chain node, use its address as RPC, for example tcp://localhost:26657.

export CHAIN_ID=smartnodes-test-1
export RPC=PUBLISHED_AT_LAUNCH
export TX="--chain-id $CHAIN_ID --node $RPC --gas auto --gas-adjustment 1.5 --gas-prices 0.025usnode"

1. Prepare the server

On the server, update it, install the tools, and open the ports: SSH, the node's port 51820 (TCP and UDP), and 443 for the disguise on an entry or bridge.

sudo apt update && sudo apt upgrade -y
sudo apt install -y git build-essential jq curl ufw wireguard-tools iproute2 iptables unzip
sudo ufw allow OpenSSH
sudo ufw allow 51820
sudo ufw allow 443/tcp
sudo ufw enable

Then make sure nothing about users can reach the disk: turn swap off and keep system logs in memory.

sudo swapoff -a
sudo sed -i.bak '/\sswap\s/s/^/#/' /etc/fstab
sudo mkdir -p /etc/systemd/journald.conf.d
printf '[Journal]\nStorage=volatile\nRuntimeMaxUse=64M\n' | sudo tee /etc/systemd/journald.conf.d/smartnode.conf
sudo systemctl restart systemd-journald

Check: swapon --show prints nothing, and sudo ufw status lists 51820 and 443/tcp. Encrypted swap is also accepted, if you need swap.

2. Install the programs

cd /tmp
curl -LO https://go.dev/dl/go1.26.11.linux-amd64.tar.gz
sudo rm -rf /usr/local/go && sudo tar -C /usr/local -xzf go1.26.11.linux-amd64.tar.gz
echo 'export PATH=$PATH:/usr/local/go/bin' >> ~/.profile && source ~/.profile

git clone https://github.com/mspvantage/smartnodes.git ~/smartnodes
cd ~/smartnodes
go build -o bin/ ./cmd/...
sudo install -m 0755 bin/smartnode bin/smartnodesd bin/smartprobe bin/smartvpn /usr/local/bin/

For an entry, bridge or prober, also install Xray: download the Linux file for your machine from the Xray releases page, check its checksum there, then:

unzip Xray-linux-64.zip xray
sudo install -m 0755 xray /usr/local/bin/xray

Check: smartnode -h lists its options, smartnodesd version prints a version, and xray version prints one if you installed it.

On your own computer, install smartnodesd the same way (go build -o bin/ ./cmd/smartnodesd); it is all you need there.

3. Your operator key (on your computer)

smartnodesd keys add operator --keyring-backend file

It prints an address and 24 words: write them on paper and keep them offline. This key owns the node's bond and receives its earnings. Get test SNODE from the faucet for this address: the bond plus about 10 SNODE for fees.

Check: smartnodesd query bank balances $(smartnodesd keys show operator -a --keyring-backend file) --node $RPC shows the test SNODE.

4. The node's keys (on the server)

The node has its own WireGuard key, which identifies it to users, and a service key, which can only redeem the tickets users pay with. Payments always go to your operator key.

sudo mkdir -p /etc/smartnode && sudo chmod 700 /etc/smartnode
sudo sh -c 'umask 077; wg genkey > /etc/smartnode/node.key'
sudo wg pubkey < /etc/smartnode/node.key

sudo smartnodesd keys add nodeservice --keyring-backend test --home /etc/smartnode/keys

Note the public key from the third line and the service key's address. The service key uses the test keyring because the node must use it unattended; that is why it holds only a few SNODE for fees, and lives in a folder only root can read. You do not need to write down its words.

Check: sudo ls -l /etc/smartnode shows node.key readable by root only (-rw-------).

5. Register the node (on your computer)

An entry node (tier 1), with the server's address, the node's public key from step 4, and its bond:

smartnodesd tx registry register-node SERVER_IP:51820 NODE_PUBLIC_KEY 1 1000000000usnode \
  --from operator --keyring-backend file $TX

For an exit, use tier 2 and 5000000000usnode. 1 SNODE = 1,000,000 usnode. Then find the node's id:

smartnodesd query registry list-node --node $RPC -o json | \
  jq -r '.node[] | select(.endpoint=="SERVER_IP:51820") | (.id // "0")'

Check: the first command prints code: 0, and the second prints a number: your node id. The first node ever registered has id 0.

6. Give the node its service key (on your computer)

smartnodesd tx registry set-service-key NODE_ID SERVICE_ADDRESS --from operator --keyring-backend file $TX
smartnodesd tx bank send operator SERVICE_ADDRESS 5000000usnode --keyring-backend file $TX

The second line gives the service key 5 SNODE for fees.

Check: smartnodesd query registry get-node NODE_ID --node $RPC shows your service_key.

7. Write the node's settings (on the server)

sudo cp ~/smartnodes/deploy/smartnode@.service /etc/systemd/system/
sudo cp ~/smartnodes/deploy/node.env.example /etc/smartnode/entry.env
sudo chmod 600 /etc/smartnode/entry.env
sudo nano /etc/smartnode/entry.env

In the file, replace each CHANGE: your node id, the chain id, and your chain endpoint's address. For an exit, delete the three -reality options. Name the file after the node (entry.env, exit.env); the name is used in the next step.

Check: grep -c CHANGE /etc/smartnode/entry.env prints 0.

8. Start it

sudo systemctl daemon-reload
sudo systemctl enable --now smartnode@entry
journalctl -fu smartnode@entry

Check: the log says the node is serving, with its id and public key, and no warnings. With -strict the node refuses to start if swap is on, if logs go to disk, or if it was given the operator key: the log says which. Press Ctrl+C to stop watching.

9. Publish the disguise (entry nodes)

The first time an entry starts with the disguise, its log prints a smartnodesd tx registry set-reality ... command with the disguise's public details, ending in --from <operator>. Run that command on your computer, with the end changed to --from operator --keyring-backend file $TX.

Check: restart the node (sudo systemctl restart smartnode@entry); its log now says the disguise on the chain matches.

Your node is now listed and serving. Probers will begin testing it within a few rounds.

Run a bridge

A bridge is an entry node whose address is on no public list. Do steps 1 to 4 and 6, but instead of step 5:

  1. On the server, make the bridge's line and see its fingerprint: 
    sudo smartnode bridge-line -key-file /etc/smartnode/node.key -listen 127.0.0.1:51830 \
  -reality-port 443 -reality-dir /var/lib/smartnode -bridge-address SERVER_IP
  2. On your computer, register it by fingerprint alone: 
    smartnodesd tx registry register-bridge FINGERPRINT 1000000000usnode --from operator --keyring-backend file $TX
  3. In its settings file, use -listen 127.0.0.1:51830 -iface sb0 -subnet 10.79.0.0/24 and add -bridge-address SERVER_IP; keep the three -reality options. Close port 51820 (sudo ufw delete allow 51820): a bridge is reached only through port 443.
  • The bridge answers paid requests for its line by itself. You are paid after a waiting period in which buyers can prove a false answer; a proven false answer burns 10% of the bond.
  • When its log says MOVE THIS BRIDGE, its line has been given out as often as allowed, or reported as not working. Change the port or address, make a new line (step 1), and publish its fingerprint with smartnodesd tx registry update-bridge BRIDGE_ID NEW_FINGERPRINT --from operator --keyring-backend file $TX.
  • To give your line privately to people you choose: sudo smartnode bridge-line ... -node-id BRIDGE_ID. Anyone who has it can find the bridge.

Earnings

  • Tickets: each ticket your node redeems pays your operator key its price, less a 5% protocol fee. The node does this by itself.
  • Availability: passing verification earns a share of the node reward pool. Claim it whenever you like: 
    smartnodesd tx verify claim-node-reward NODE_ID --from operator --keyring-backend file $TX

All figures are drafts; see the token page.

Checks and jail

Probers test your node at random through real sessions. If it fails several rounds in a row it is jailed: hidden from users until you fix it and run smartnodesd tx verify unjail NODE_ID --from operator --keyring-backend file $TX. Being offline costs income, never bond; only proven tampering with traffic burns bond. Check your node's record with smartnodesd query verify node-record NODE_ID --node $RPC. On the test network, penalties are recorded but not applied at first.

Leaving

smartnodesd tx registry deregister-node NODE_ID --from operator --keyring-backend file $TX
# after the unbonding period (21 days, draft):
smartnodesd tx registry withdraw-bond NODE_ID --from operator --keyring-backend file $TX

Stop the node on the server once it has deregistered: sudo systemctl disable --now smartnode@entry.

Run a prober

Probers are paid to test nodes. Use a server that is not one of your nodes, and do steps 1 and 2 there (Xray included).

  1. On the server, make the prober's key, and note its address: 
    sudo mkdir -p /etc/smartnode && sudo chmod 700 /etc/smartnode
sudo smartnodesd keys add prober --keyring-backend test --home /etc/smartnode/keys
  2. Get test SNODE from the faucet for that address: 1,000 SNODE for the bond, plus some to buy test tickets and pay fees. Then register: 
    sudo smartnodesd tx verify register-prober 1000000000usnode --from prober \
  --keyring-backend test --home /etc/smartnode/keys $TX
  3. Give it a ticket wallet at /etc/smartnode/prober-wallet.json (see Get tickets), readable by root only.
  4. Install and start it: 
    sudo cp ~/smartnodes/deploy/smartprobe.service /etc/systemd/system/
sudo cp ~/smartnodes/deploy/probe.env.example /etc/smartnode/probe.env
sudo chmod 600 /etc/smartnode/probe.env
sudo nano /etc/smartnode/probe.env      # replace each CHANGE
sudo systemctl daemon-reload && sudo systemctl enable --now smartprobe

Check: journalctl -fu smartprobe shows it asking each round which nodes to test, then testing and reporting them.

If something goes wrong

What you seeWhat to do
"swap ... is not encrypted"Swap is on. Step 1: sudo swapoff -a and the /etc/fstab line.
"system logs are kept on disk"Step 1: the journald setting, then sudo systemctl restart systemd-journald.
"-from is the operator's own key"The settings file names the operator key. Use the service key (step 6).
"insufficient fees" or "account not found"The key has no SNODE for fees: send it some, and wait a block.
Users cannot connectCheck the firewall (sudo ufw status) and your provider's firewall for 51820 TCP and UDP, and 443 for the disguise.
The node is jailedLook at its record (Checks and jail), fix the cause, then unjail.

Still stuck? Open an issue on GitHub with what you ran and what it printed. Never include your 24 words or any key file.
