Run a validator

Validators run the SmartNodes chain: they agree on every block and vote on its rules. This guide takes a fresh Linux server to a working validator. Every step ends with a check; do not move on until it passes.

{net:notice}

What a validator does, and this chain's rules

  • At most 30 validators are active: those with the most stake.
  • Commission must be between 5% and 20%. The maximum you set when you create the validator can never be raised later, so choose it with care.
  • Half of validator income is shared equally among validators whose operator stakes at least 5,000 SNODE of their own with them. The other half goes by stake.
  • A validator that signs two different blocks at the same height loses part of its stake and is removed for good. This happens if the same key runs on two machines at once. Step 10 is about avoiding it.
  • A validator that is offline for too long is jailed: it stops earning until you unjail it.

You will need: a server with at least 4 CPU cores, 16 GB of memory and 200 GB of SSD storage (a starting point, which will grow), a fixed public IP address, and about an hour. Your own computer is only needed to connect to it.

Commands below that need these values use shell variables. Set them once, in every new terminal:

export CHAIN_ID={net:chain_id}
export GENESIS_URL={net:genesis_url}
export GENESIS_SHA256={net:genesis_sha256}
export SEEDS="{net:seeds}"

1. Prepare the server

Log in as a user with sudo. Update the system, install the tools, and open only the ports a validator needs: SSH, and 26656 for the chain's peer-to-peer traffic.

sudo apt update && sudo apt upgrade -y
sudo apt install -y git build-essential jq curl ufw
sudo ufw allow OpenSSH
sudo ufw allow 26656/tcp
sudo ufw enable
sudo adduser --disabled-password --gecos "" smartnodes

The last line makes a separate user, smartnodes, that runs the node, so it has no other rights on the server.

Check: sudo ufw status lists OpenSSH and 26656/tcp, and timedatectl says System clock synchronized: yes. A wrong clock causes missed blocks.

2. Install the programs

Install Go, then build smartnodesd and Cosmovisor, the helper that switches to new versions at agreed upgrades.

cd /tmp
curl -LO https://go.dev/dl/go1.26.11.linux-amd64.tar.gz
sudo rm -rf /usr/local/go && sudo tar -C /usr/local -xzf go1.26.11.linux-amd64.tar.gz
echo 'export PATH=$PATH:/usr/local/go/bin:$HOME/go/bin' >> ~/.profile && source ~/.profile

git clone {repo}.git ~/smartnodes
cd ~/smartnodes
go build -o bin/ ./cmd/smartnodesd
sudo install -m 0755 bin/smartnodesd /usr/local/bin/

go install cosmossdk.io/tools/cosmovisor/cmd/cosmovisor@latest
sudo install -m 0755 ~/go/bin/cosmovisor /usr/local/bin/

For an ARM server, use linux-arm64 in the Go file name.

Check: go version shows go1.26, and smartnodesd version prints a version. Until ready-made releases exist, build the release the network announces: git checkout its tag before go build.

3. Set up the node

From here on, work as the smartnodes user. Choose a public name for your validator (its moniker).

sudo -iu smartnodes
export CHAIN_ID={net:chain_id}
export GENESIS_URL={net:genesis_url}
export GENESIS_SHA256={net:genesis_sha256}
export SEEDS="{net:seeds}"
smartnodesd init "your-validator-name" --chain-id $CHAIN_ID

The export lines set the network details for this user's session. If you log out and back in, run them again.

Check: ls ~/.smartnodes/config shows config.toml, app.toml, genesis.json, node_key.json and priv_validator_key.json.

4. Get the genesis file

The genesis file is the network's starting state. Every validator must have exactly the same one, so check its fingerprint.

curl -fsSL "$GENESIS_URL" -o ~/.smartnodes/config/genesis.json
echo "$GENESIS_SHA256  $HOME/.smartnodes/config/genesis.json" | sha256sum -c -
smartnodesd genesis validate

Check: sha256sum prints OK, and the last command says the file is valid. If the fingerprint does not match, stop: you have the wrong file.

5. Configure

sed -i -e "s|^seeds = .*|seeds = \"$SEEDS\"|" \
       -e "s|^external_address = .*|external_address = \"YOUR_PUBLIC_IP:26656\"|" ~/.smartnodes/config/config.toml
smartnodesd config set app minimum-gas-prices {net:min_gas_price}
smartnodesd config set client chain-id $CHAIN_ID
smartnodesd config set client keyring-backend file

Replace YOUR_PUBLIC_IP with the server's address. The first command edits config.toml directly, because smartnodesd config set only changes app.toml and client.toml. The file keyring keeps keys encrypted with a password you choose.

Check: grep -E '^(seeds|external_address)' ~/.smartnodes/config/config.toml shows your values.

6. Set up Cosmovisor

export DAEMON_NAME=smartnodesd DAEMON_HOME=$HOME/.smartnodes
cosmovisor init /usr/local/bin/smartnodesd
exit

exit returns you to your own user.

Check: sudo ls /home/smartnodes/.smartnodes/cosmovisor/current/bin shows smartnodesd.

7. Start the node and let it sync

sudo cp ~/smartnodes/deploy/smartnodesd.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now smartnodesd
journalctl -fu smartnodesd

The log should show blocks being received. Press Ctrl+C to stop watching; the node keeps running.

Check: wait until this prints false, which means the node has caught up with the network. It can take from minutes to hours.

smartnodesd status | jq .sync_info.catching_up

If it stays at block 0 with no peers, see If something goes wrong.

8. Make your validator's key

sudo -iu smartnodes
smartnodesd keys add validator

It asks for a keyring password, then prints an address and 24 words. Write the words on paper and keep them offline. They are the only way to recover the key; anyone who has them controls it. Never type them into a website or a message.

Get test SNODE from the faucet for the printed address, enough for your stake plus fees (at least 5,000 SNODE to receive the equal share).

Check: smartnodesd query bank balances $(smartnodesd keys show validator -a) shows your test SNODE (1 SNODE = 1,000,000 usnode).

9. Become a validator

Only once step 7's check prints false. Write a file describing your validator:

cat > ~/validator.json <<JSON
{
  "pubkey": $(smartnodesd comet show-validator),
  "amount": "5000000000usnode",
  "moniker": "your-validator-name",
  "identity": "",
  "website": "",
  "security": "",
  "details": "",
  "commission-rate": "0.10",
  "commission-max-rate": "0.20",
  "commission-max-change-rate": "0.01",
  "min-self-delegation": "1"
}
JSON
smartnodesd tx staking create-validator ~/validator.json --from validator \
  --gas auto --gas-adjustment 1.5 --gas-prices {net:min_gas_price}
  • amount is your own stake: 5,000 SNODE here.
  • commission-rate is what you charge now: 10% here. It must be at least 5%.
  • commission-max-rate can never be raised later, and may not be above 20%.

Check: the command prints code: 0. Then:

smartnodesd query staking validator $(smartnodesd keys show validator --bech val -a) | grep -E 'moniker|status'

shows your name and BOND_STATUS_BONDED, once you are among the 30 with the most stake.

10. Back up, and never run the key twice

  • Copy ~/.smartnodes/config/priv_validator_key.json to safe offline storage. It is the key that signs blocks.
  • Never start a second machine with the same key while the first is running, not even briefly to test. Two machines signing for one validator is double-signing: part of the stake is burned and the validator is removed for good.
  • To move to a new server: stop the old one, make sure it cannot restart (sudo systemctl disable --now smartnodesd), wait for a few blocks, and only then start the new one.

Type exit to return to your own user.

Run these as the smartnodes user (sudo -iu smartnodes).

Upgrades

Upgrades are agreed by governance vote and happen at a set block. Before that block, build the announced version and put it where Cosmovisor looks for it, under the upgrade's name:

sudo -iu smartnodes
mkdir -p ~/.smartnodes/cosmovisor/upgrades/UPGRADE_NAME/bin
cp /path/to/new/smartnodesd ~/.smartnodes/cosmovisor/upgrades/UPGRADE_NAME/bin/

At the upgrade block the node stops, Cosmovisor switches to the new version and starts it again. Watch the log at that time.

Genesis validators (invited, Phase A)

The first validators are in the genesis file from the start. If you were invited:

  1. Do steps 1 to 3, and step 8 to make your key. Send the address to the coordinator, who gives it test SNODE in the draft genesis file.
  2. Put the draft genesis file you receive in ~/.smartnodes/config/genesis.json, then make your signed genesis transaction: 
    smartnodesd genesis gentx validator 5000000000usnode --chain-id $CHAIN_ID \
  --moniker "your-validator-name" --commission-rate 0.10 --commission-max-rate 0.20 --commission-max-change-rate 0.01
  3. Send the file it names (in ~/.smartnodes/config/gentx/) to the coordinator. It holds only public information.
  4. When the final genesis file is published, continue from step 4. Skip step 9: you are already a validator.

If something goes wrong

What you seeWhat to do
No peers, stuck at block 0Check the seeds in step 5, that port 26656 is open (sudo ufw status), and that your provider's firewall allows it too.
sha256sum says FAILEDWrong genesis file. Download it again from the address above.
"maximum commission is above the ceiling"commission-max-rate is above 0.20. Lower it.
"insufficient fees"Add --gas-prices {net:min_gas_price} to the command.
"account not found"The key has no test SNODE yet: use the faucet, and wait a block.
Status BOND_STATUS_UNBONDEDYou are not among the 30 with the most stake, or the node is not caught up.
JailedThe node was offline. Fix it, wait until it has caught up, then unjail (Day to day).

Still stuck? Open an issue on GitHub with the command you ran and what it printed. Never include your 24 words or any key file.
